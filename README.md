# SoftwareEngineering
软件工程实验小组作业-版本控制与团队协作




## 团队协作规范
为保障后续协作效率，小组共同制定以下协作规范：
1. 提交频率规范
•	每日开发结束前必须将本地代码推送至远程feature分支，确保代码备份；
•	每完成1个独立小功能点（如单个接口、单个页面逻辑）需进行1次代码提交，避免单次提交大量无关联代码；
•	提交前需自行检查代码语法错误、测试功能可用性，确保提交代码可运行。
2. 代码审查要求
•	PR评审需在24小时内响应，避免延误开发进度；
•	评审重点：代码命名规范（变量、函数名清晰易懂）、逻辑合理性、是否存在冗余代码、是否符合模块功能需求；
•	评审意见需具体可落地（如“此处应增加参数校验”而非“代码有问题”），开发者需积极响应并修改；
•	合并前必须获得至少1名reviewer的审批通过，严禁未经评审直接合并。
3. 分支使用规范
•	严禁直接向master、dev分支推送代码，所有代码均通过feature分支+PR合并；
•	feature分支命名规范：“feature/模块名称”，如：
“feature/user”“feature/manage-book”；
•	开发过程中若需新增功能，需基于最新dev分支创建新的feature分支，避免基于旧分支开发。
